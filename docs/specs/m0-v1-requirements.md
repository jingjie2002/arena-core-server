# 竞域 arena-core-server v1 需求基线

- 状态：已锁定
- 日期：2026-08-11
- 适用范围：M0 至 M8
- 上位方案：`plans/arena-core-server-master-plan-2026-08-11.md`

## 1. 产品目标

构建一个可在 WSL2 Ubuntu 环境复现的 C++17 联机服务端项目，用一条完整且可验证的链路展示：TCP/Protobuf 会话、心跳与断线重连、1v1 匹配、房间准备、服务端确定性结算、MySQL 持久化、Redis 排行榜以及 Web 观测面板。

v1 面向简历展示和技术面试，不是商业游戏。它强调并发边界、状态机、幂等、故障恢复和可复现工程，而不是画面或复杂玩法。

## 2. v1 明确包含

- C++17 模块化单体服务，单进程承载网络、会话、匹配、房间、结算和观测接口。
- TCP 长连接，4 字节大端长度帧，消息体为 Protobuf。
- Hello 建立会话、心跳、超时清理、15 秒重连窗口和请求幂等。
- 单一 `duel` 模式的 1v1 匹配，按等待时间扩展分差窗口。
- 带玩家绑定的一次性房间加入凭证、双方准备和服务端生成的确定性结果。
- MySQL 作为结算事实源；Redis 用作临时状态、队列及排行榜缓存。
- Redis Lua 保证关键队列操作原子性；嵌入 Lua 5.4 承载版本化的匹配与计分规则。
- 只读 Web 观测面板、事件流、Robot/E2E、故障注入、Sanitizer 和 fresh-clone 验证。

## 3. v1 明确不包含

- 游戏画面、移动同步、战斗、技能、道具、观战玩法或客户端权威结果。
- 微服务拆分、Kubernetes、云部署、公开生产环境或商业级账号系统。
- 将 Go CoreRank 逐行翻译为 C++，或修改 CoreRank 原仓库。
- M8 之前的无关性能优化、抽象升级或功能扩张。

## 5. 需求编号

| ID | 必须满足的行为 |
|---|---|
| SYS-001 | 服务可从配置启动，依赖不可用时给出可定位错误并按策略退出或降级。 |
| NET-001 | TCP 流按 4 字节大端长度正确拆包、粘包，单帧负载不超过 64 KiB。 |
| NET-002 | 不支持的版本、类型、非法帧和解码失败返回稳定错误并关闭连接。 |
| SES-001 | 客户端在 5 秒内完成 Hello，服务端签发会话与重连凭证。 |
| SES-002 | 默认每 10 秒心跳，30 秒无活动会话被清理。 |
| SES-003 | 非主动断线后 15 秒内可凭有效凭证恢复同一玩家上下文。 |
| SES-004 | 会话关闭、超时、服务停止均幂等，不重复释放资源。 |
| MAT-001 | 合法玩家可进入 `duel` 队列并获得稳定票据。 |
| MAT-002 | 同一玩家同一模式不能同时存在两个排队票据。 |
| MAT-003 | 票据可取消、会过期，并且终态不可逆。 |
| MAT-004 | 匹配隔离模式，按等待时间扩大允许分差，并保持确定性候选顺序。 |
| MAT-005 | 房间容量不足或分配失败时，仍有效的票据安全回队，不能丢失或双重匹配。 |
| ROM-001 | 玩家只能用与 match/room/server/player 绑定的有效加入凭证进入房间。 |
| ROM-002 | 双方加入并准备后，房间只推进一次 Running、Settling、Closed。 |
| ROM-003 | 断线重连不破坏房间成员关系；过期或终止按状态机收敛。 |
| SET-001 | 权威结果只能由服务端内部房间流程产生，客户端不能提交比赛结果。 |
| SET-002 | 结算、玩家分数和修复任务在一个 MySQL 事务中一致提交。 |
| SET-003 | 同一指纹重复结算返回原结果；不同指纹重复结算报告冲突。 |
| RNK-001 | Redis 提供排行榜缓存，排序和并列规则稳定。 |
| RNK-002 | Redis 更新失败不回滚已提交事实，并可由 MySQL 脏记录修复。 |
| LUA-001 | 匹配和计分规则脚本版本化、可校验、确定性执行，失败时不可产生半状态。 |
| OBS-001 | 观测端只读取不可变快照和事件，不直接触碰业务对象。 |
| QA-001 | Robot 能完成连接、匹配、进房、准备、结算和查榜的端到端流程。 |
| QA-002 | 固定随机种子、故障注入和事件回放可复现关键失败路径。 |
| OPS-001 | 服务按停止接入、停止撮合、排空房间、完成存储、关闭资源的顺序退出。 |
| REL-001 | 新环境按文档从 fresh clone 构建、测试并运行演示链路。 |

每项需求与验证证据的映射见 `docs/quality/requirements-test-matrix.md`。

## 6. 全局约束

- 玩家标识长度为 1 至 64，只允许 ASCII 字母、数字及 `_ - : .`。
- MMR 范围为 0 至 10000。
- 所有公开状态转换必须由唯一所有者串行执行；阻塞式存储调用不得占用网络或业务 strand。
- 日志不得记录明文会话令牌、重连令牌、加入凭证、数据库密码或其他密钥。
- 未通过相应测试的能力不能在报告中宣称完成。

- 协议、状态机、错误码、数据模型、并发所有权和三项关键 ADR 均形成版本化文档。
