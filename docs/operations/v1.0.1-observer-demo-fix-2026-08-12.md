# v1.0.1 观察台按钮修复记录

## 用户看到的现象

在 `http://127.0.0.1:49120/` 依次点击三个演示按钮，都会出现红色结果卡：

- 演示没有完成
- 服务器暂时无法完成这项操作

这不是用户操作错误。

## 根因

页面会向 `/api/demo/scenarios/{scenario}` 发送带 `X-Arena-Demo: 1` 的 POST 请求，但重启后的 `.runtime/arena-core.json` 中 `observer.demo_mode` 为 `false`。服务器因此对三个请求统一返回 HTTP 403：

```json
{"error":"demo_mode_disabled"}
```

原因位于 `scripts/demo-up.sh`：为了让核心容器在 Docker 私有网络中监听 `0.0.0.0`，上一次发布修复关闭了 Demo，却没有同步处理由宿主机 loopback HAProxy 提供的本地安全边界。

## 实施修复

1. 为 Observer 配置增加 `allow_non_loopback_demo`，只允许显式声明的受信任代理场景绕过“核心进程必须直接绑定 loopback”的校验。
2. 保留普通非 loopback Demo 的拒绝逻辑，并拒绝“只开代理例外、却没有开 Demo”的矛盾配置。
3. `scripts/demo-up.sh` 同时生成 `demo_mode=true` 与 `allow_non_loopback_demo=true`；Compose 仍只由 HAProxy 发布宿主机 `127.0.0.1:49120`。
4. `scripts/smoke.sh` 用不存在的演示场景做无副作用探针：正确启用时返回 404；未启用时会返回 403 并使 smoke 失败。
5. 发布补丁版本 `1.0.1`，新增两项配置回归测试。
