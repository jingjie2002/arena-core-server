2. 扩展 `arena-core-robot`：保留旧心跳入口，新增 JSON 场景、结构化报告、`--replay` 和延迟统计。
3. 新增真实 TCP E2E：记录、重启回放、8 人/4 房间、活跃连接停机和重启回归。
4. 新增重复依赖故障序列与排队/已入房状态的幂等停机测试。

7. 临时隔离 MySQL/Redis 在两套构建中各完成 12/12，并跑过完整 Robot 数据链。
8. ASan+UBSan 完成 80/80 和真实 E2E；TSan 缩小集完成 50/50。
9. 500 连接首次预检发现 Robot 事件句柄浪费；共享 I/O 上下文后，5 秒预检通过。
10. 正式运行 500 连接、250 房间、600 秒，业务错误 0；生成稳定性报告。

## 中途失败及处理

- Robot 最初把 `duration_seconds=0` 当成无限保持，完整链路成功后不退出；改为 0 表示立即结束。
- 连续场景复用玩家身份撞到 15 秒重连保护；为不同场景使用不同固定种子。
- 并发 Robot 最初使用超出 0—10000 契约的 MMR 分段；改为接受真实动态配对，并按服务返回的 match/room 汇合核对。
- E2E 脚本两次读取错观察 API 字段；最终使用 `counts.sessions_online` 与 `counts.rooms_total`。
- 停机测试一度使用非法 MMR 50000；改为合法且能独立排队的 5000。
- GCC TSan 被 Boost.Asio fence 工具链提示和 `-Werror` 阻断；仅在 TSan 构建中保留警告但不升级为错误。
- 500 连接预检受每进程 1024 文件句柄限制；没有提升系统限制，而是让 Robot socket 共享 Asio I/O 上下文。

所有失败均保留为 M7 调试证据，并在最终实现上重新完成对应回归。

M7 通过，不需要人工补测。下一计划内人工介入仍是 M8 的 fresh-clone 与公开发布决定。
