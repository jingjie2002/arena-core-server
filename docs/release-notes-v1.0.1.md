# 竞域 1.0.1 修复说明

发布日期：2026-08-12

## 结论

`1.0.1` 修复了本机 Compose 观察台中三个演示按钮始终显示“服务器暂时无法完成这项操作”的问题。页面、真实 TCP 业务、MySQL 和 Redis 本身没有损坏；问题是 Docker 启动配置错误地关闭了演示写入口。

## 修复内容

- Compose 启动脚本现在显式启用演示模式，并声明核心服务位于受宿主机 loopback 网关保护的 Docker 私有网络中。
- 普通非 loopback 配置仍不能直接启用演示写入口；只有显式的受信任代理配置可以通过校验。
- Compose smoke 新增演示入口探针，能够在页面按钮再次被后台关闭时直接阻止启动验收通过。
- 项目版本、CI 版本契约和发布脚本测试计数更新为 `1.0.1` / `82`。

## 验证证据

- GCC：82/82 通过；Clang：82/82 通过。
- Docker 镜像内 GCC：82/82 通过；真实 Robot、MySQL、Redis、观察台和演示入口 smoke 通过。
- 隔离 clean-copy：全新临时源码目录 GCC 82/82、独立 Compose 和完整 smoke 通过。
- 真实浏览器依次点击三项，分别显示“完整比赛演示通过”“重复提交保护通过”“排行榜故障已经自动恢复”；页面错误日志为 0。

## 安全边界

演示入口仍只用于本机展示。HAProxy 仅发布到宿主机 `127.0.0.1`，核心容器、MySQL 和 Redis 不发布到公网。本修复不增加账号鉴权、TLS 或公网部署能力。
