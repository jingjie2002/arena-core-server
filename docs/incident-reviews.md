# 真实故障复盘

这里保留开发中真实出现、被复现并重新验证的问题，不把一次性失败从记录中删除。

## BUG-M5-TZ-001：dirty 修复时间比较错位

- 现象：Redis 失败后 dirty 行存在，但在数据库会话时区为 `+08:00` 时，到了重试时间仍可能无法被修复任务选中。
- 根因：列使用 `TIMESTAMP`，写入/比较却使用 `UTC_TIMESTAMP()`；MySQL 对 `TIMESTAMP` 做会话时区转换，两个时间口径错位。
- 修复：统一使用 `CURRENT_TIMESTAMP(6)`，让列和值遵循同一会话时区语义。
- 复测：真实 MySQL/Redis dirty 保留、恢复重放、清理和全量重建测试在 GCC/Clang 两套构建通过。

## BUG-M7-FD-001：500 Robot 只有 255 个连接

- 现象：首次 500 连接预检中，255 个成功、245 个报 `Too many open files`。
- 根因：每个 Robot socket 都额外拥有一个 Asio `io_context`；Linux 后端为每个上下文消耗事件句柄，在 WSL 每进程 1024 文件句柄限制下提前耗尽。
- 修复：500 个独立 socket 共享一个 Robot I/O 上下文，不提高 `ulimit` 掩盖设计浪费。
- 复测：5 秒预检和 600 秒正式测试均达到 500 连接/250 房间、业务错误 0；最终实现再经过 ASan+UBSan、E2E 和目标 TSan 回归。

## BUG-M7-REPLAY-001：固定种子仍不能稳定重放

- 现象：双 Robot 并发入队时，同一固定种子偶尔由不同玩家先入队，业务结果核对产生漂移；连续场景还会撞到 15 秒身份重连保护。
- 根因：随机种子只固定数据，不固定线程调度；不同场景复用玩家身份也不符合 Session 生命周期。
- 修复：单对回放增加 20 ms 确定性入队错峰；不同场景使用不同固定种子；并发场景按服务实际 match/room 聚合，不假设线程顺序。
- 复测：服务重启后的 `--replay` 通过，8 人动态配对仍形成 4 个合法房间。
