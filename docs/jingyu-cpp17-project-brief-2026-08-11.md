# 竞域 C++17 项目简要介绍与执行摘要

## 一句话介绍

`竞域`是一套使用C++17、Boost.Asio、Protobuf、Redis、MySQL和Lua实现的游戏匹配、房间、排行榜与结算服务，能够通过机器人客户端完成从连接、匹配、入房、准备、结束、结算到排行更新的完整闭环。

## 为什么做这个项目

现有Go CoreRank已经有较完整的匹配、排行和结算业务，但简历缺少一份能够直接证明C++游戏服务端能力的主项目。竞域不逐行翻译Go代码，而是继承业务规则，重新设计C++17异步网络、Session生命周期、房间状态机、并发归属、事务结算、缓存修复和QA复测体系。

## 最终能看到什么

- `arena-core-server`接受真实TCP/Protobuf连接。
- `arena-core-robot`模拟玩家完成心跳、匹配、入房、准备和结算流程。
- Redis保存匹配队列、临时状态和排行榜缓存。
- MySQL保存不可丢失的比赛与结算事实。
- Lua承载匹配窗口和积分规则。
- 浏览器观察台展示Session、队列、房间、结算、排行和QA场景。
- 自动测试覆盖协议异常、断线重连、重复结算、Redis/MySQL故障、并发与优雅停机。
- 全新WSL2环境只需Git与Docker/Compose，即可从GitHub克隆后无手工改配置启动Demo、运行smoke并打开观察台。

## C++17方案的关键特点

- Boost.Asio回调/完成处理器实现异步TCP，不依赖C++20协程。
- 每个Session和Room通过strand串行修改自身状态，不依靠大范围加锁。
- `shared_ptr/weak_ptr`管理异步对象生命周期，所有关闭路径统一进入`Stop()`。
- `std::thread`网络/存储线程池配合`signal_set`、停止状态和显式`join()`完成优雅停机。
- 4字节大端长度帧配合Protobuf解决消息边界、半包、粘包和非法长度问题。

选择C++17不是降低项目要求，而是让项目与当前课程标准一致。项目仍然完整覆盖异步网络、并发、生命周期和数据一致性，只是不使用C++20协程替代这些核心问题。

## 完成标准

项目只有在以下证据同时存在时才算完成：

- C++17 GCC/Clang构建和CI通过。
- TCP/Protobuf/Session/匹配/房间/结算/排行全链路运行。
- Redis、MySQL和Lua真实接入，并覆盖失败恢复路径。
- 单元、协议、组件、集成、E2E、故障和发布回归测试通过。
- ASan/UBSan通过，目标并发测试有TSan或明确限制说明。
- 机器人稳定性测试产生真实CPU、内存、延迟和错误率报告。
- 至少保存两份真实Bug的复现、修复和复测记录。
- 浏览器可以观察业务状态并运行本地Demo场景。

工程完成后还不能直接写入简历。Session、匹配/房间、结算/排行和QA四个核心模块都必须达到“能独立解释主链、完成小修改并回归”的掌握门槛，其中至少两个模块要能现场定位故障、说明取舍并验证修改。

## 明确边界

项目不制作游戏画面、战斗、地图、技能、帧同步或完整账号系统，也不拆成微服务、不做Kubernetes、多机高可用或云服务器部署。它追求的是一条完整、可解释、可测试、可从GitHub独立复现的应届生C++游戏服务端核心链路，而不是堆叠无法完成的功能数量。

## 预计周期

- 功能闭环：约2—3周工程实现。
- 达到简历主项目质量：约4—6周。
- 依赖、并发或环境问题反复时：预留到6—8周。

上述时间是工程实施时间，不等于学习掌握时间；是否能写入简历还取决于本人能否运行、解释、修改和复测项目。

## 已确认规格

1. 中文展示名：`竞域`。
2. 仓库名：`arena-core-server`。
3. 语言标准：C++17。
4. 主运行环境：WSL2 Ubuntu。
5. Web观察台与可点击Demo：必做。
6. GitHub fresh clone：必做，不能依赖作者机器的缓存、数据库或私有配置。
7. 云服务器：不纳入项目范围。

## GitHub拉取即用标准

演示主入口计划固定为`git clone`后依次运行`./scripts/doctor.sh`、`./scripts/demo-up.sh`和`./scripts/smoke.sh`。脚本负责前置检查、运行配置生成、MySQL迁移、种子数据、依赖启动和健康等待；README提供观察台地址、预期结果和故障排查。另保留CMake Presets原生构建与CTest路径，用于证明源码不是只能在成品容器中运行。M8发布前必须在全新目录或干净CI checkout复测整套流程。
