# M7 交接：Robot、故障与稳定性

## 你现在只需要知道什么

项目现在不只是在网页上“看起来能运行”，还有一批 Robot 真正连接服务端，自动完成匹配、房间、结算和排行。

M7 已证明三件事：

1. 同一个场景能记录并在重启后重放，业务结果不会悄悄变化。
2. MySQL/Redis 失败、重复请求、断线恢复和停机路径有自动检查。
3. 本机实测 500 个连接、250 个房间保持 10 分钟，业务错误为 0。

## 主要入口

- `scenarios/qa/`：小回归、回放、停机、500 连接预检和正式长测场景。
- `arena-core-robot --scenario FILE --output REPORT`：执行场景并写报告。
- `arena-core-robot --replay REPORT`：重启服务后核对先前的业务结果。
- `scripts/dev/m7-e2e.sh`：短时间完整验收。
- `scripts/dev/m7-soak.sh`：500 连接预检或 10 分钟稳定性测试。
- `docs/quality/M7-stability-report-2026-08-12.md`：关键数值与技术边界。

## 面试时暂时不要夸大的内容

- P99 约 371ms 是 500 Robot 同时启动时的完整业务闭环，不是网络 RTT，也不是极限性能。
- 250 个房间完成后连接保持 10 分钟；这不是“每秒持续创建 250 个房间”的吞吐测试。
- TSan 用的是缩小并发集，完整 500 连接场景使用普通构建；这是总计划明确采用的方式。
- M7 证明工程自动化成立，不等于你现在已经能独立解释全部源码。个人掌握度在最终交接阶段另行评估。
