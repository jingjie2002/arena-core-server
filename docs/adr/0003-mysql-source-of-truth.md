# ADR-0003：MySQL 为结算事实源，Redis 为可修复缓存

- 状态：Accepted
- 日期：2026-08-11

## 背景

比赛结算同时影响比赛状态、两名玩家分数和排行榜。先写 Redis 再旁写 MySQL 会在任一依赖失败时形成无法可靠判断的双写状态。项目需要对“半结算”给出明确答案。

## 决策

MySQL 事务是结算是否成功的唯一判据。事务原子写入 settlement、玩家分数、比赛成员结果和排行榜 dirty 记录。提交后再更新 Redis；缓存失败保留 dirty 证据，由后台修复器按 MySQL 目标值重放。

`match_id` 唯一，规范化结果 fingerprint 区分幂等重试和冲突。

## 后果

- 优点：不会出现 Redis 已改而数据库未提交的成功假象；结算可审计、可恢复。
- 代价：缓存可能短暂陈旧；排行榜写入需要修复任务和可见健康状态。
- 缓解：dirty 表、重试退避、全量重建命令和 `cache_state` 标记。

## 未采用方案

- Redis 事实源 + MySQL 旁写：恢复和审计语义不足。
- 应用层无日志双写：崩溃窗口不可关闭。
- 分布式事务：对单体 v1 过重，且没有必要。
