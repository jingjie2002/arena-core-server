# 第19次审计报告 - v1.1可操作场景实验台设计

## 基本信息
- 任务名称：明确真实控制台能否修改条件并符合游戏测试方式
- 报告时间：2026-08-12 12:47 +08:00
- 任务类型：中等任务 / 设计补充
- 本轮完成度：完成设计补充，未进入实现

## 背景与范围
- 背景说明：用户认为三个固定按钮不像正常游戏测试，希望任何使用者都能修改条件后运行测试。
- 本轮目标：定义可操作范围、真实执行方式、安全边界、重放模型以及它与正常游戏测试的关系。
- 本轮边界（明确不做什么）：不实现控制器或新页面，不开放远程访问，不允许浏览器执行任意命令或直接改数据库。

## 实现方案与取舍
- 方案概述：将控制台设计为参数化场景实验台，由独立本地 Lab Controller 校验输入、启动真实 Robot、安排受控故障、收集只读观察数据并自动断言。
- 关键取舍：允许修改测试输入和故障计划，不允许修改正在运行的业务内部状态；Observer 继续只读，避免把生产服务变成远程命令执行器。
- 备选方案及未采用原因：直接在核心服务中增加万能控制 API 虽然实现快，但安全边界差、测试不真实，也不符合服务端工程职责。

## 验证命令与结果证据
- 对照现有 Robot、Observer 只读边界、Compose loopback 限制与 v1.1 真实演示目标完成设计一致性核对。
- 参数分为玩家/时序/故障输入与受保护的工程配置，避免把“可操作”误解为“任意改内部数据”。
- 未验证项：Lab Controller 和参数化页面尚未实现，本轮不声称已经可以操作。

## 风险与回滚点
- 已知风险：若把本机控制平面直接公开到网络，会产生未认证的故障注入与进程控制风险。
- 影响范围：仅设计草案和协作状态，没有修改 v1.0.1 服务。
- 回滚策略：现有 v1.0.1 继续运行；设计补充可在用户最终确认前调整。
