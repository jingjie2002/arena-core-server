# Cleanup Rules

## 目标

在不误删有效内容的前提下，管理死代码、无用文件、历史残留和结构整理类操作。

## 默认原则

- 清理不是默认动作，先判断是否真的服务当前任务
- 发现可疑冗余时，先分类，再说明，再执行
- 高风险删除默认先确认

## 低风险删除

通常可直接处理：
- 构建产物
- 缓存文件
- 临时文件
- 可自动重新生成的文件
- 本轮刚创建且确认不再需要的文件

## 高风险删除

默认先说明并确认：
- 业务代码文件
- 配置文件
- 测试文件
- 文档文件
- 数据文件
- 无法确认用途的旧文件
- 批量目录重组、模块移除、结构性清理

## 分类建议

主分类：
1. 死代码
2. 死逻辑
3. 未使用文件
4. 过时文档
5. 可疑但暂不确定是否可删的内容

可选补充属性：
- 重复实现
- 临时调试代码
- 失效配置
- 失效依赖引用
- 不可达分支

## 说明要求

提出清理建议时，至少说明：
- 属于哪一类
- 为什么判断它可能可清理
- 与当前功能的相关性
- 清理收益
- 清理风险

## 报告要求

- 若本轮发生删除、清理、目录重组或旧模块移除，必须在报告中单独说明
- 若发现问题但本轮不处理，也应在报告中列为遗留项
